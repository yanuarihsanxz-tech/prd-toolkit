# Portable workflow research — 2026-11-03

Question: which current patterns make the toolkit easier to use across coding
assistants and make improvement claims testable without adding a provider or
another mandatory workflow?

## Evidence and decisions

| Primary source inspected | Relevant observation | Decision |
|---|---|---|
| [GitHub weekly Trending](https://github.com/trending?since=weekly) and [monthly Trending](https://github.com/trending?since=monthly) | Live HTML lists included Hallmark, Impeccable, Cloudflare's security-audit skill, Superpowers and other agent tooling | Use as discovery leads, not quality rankings or adoption evidence. No star-count metric enters acceptance. |
| [Spec Kit README](https://github.com/github/spec-kit/blob/main/README.md) | Explicit operation entry points and multiple agent integration routes | Adopt a single portable CLI and explicit operation selection over existing canonical files. Do not import its extension/runtime stack. |
| [OpenSpec README](https://github.com/Fission-AI/OpenSpec/blob/main/README.md) | Existing-project changes are a first-class workflow with concrete scenarios | Keep the existing change contract; prove it with a retained CSV defect and an unchanged before/after oracle. Do not add parallel spec/proposal/task authorities. |
| [Karpathy autoresearch](https://github.com/karpathy/autoresearch) | Small editable scope and a fixed evaluation boundary make iteration observable | Add explicit behavioral case execution and source-identified results. This is an adaptation of the pattern, not a port of the training system or an autonomous agent loop. |
| [Ponytail skill](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md) | Reuse existing code, then the standard library, and keep necessary verification | Reuse current validators and layouts; add no dependencies or persistent host mode. Do not shorten required scope to manufacture efficiency. |

The GitHub connector supplied repository source. Web retrieval initially could
not fetch the time-filtered Trending pages; HTTPS command-line retrieval then
succeeded for both periods. The plugin catalog returned no Ponytail listing;
its upstream skill was inspected as source. Catalog absence is not proof that
no third-party integration exists. No host plugin, credential, provider, runtime
or persistent instruction was installed or changed.

These sources informed design choices. They do not establish that this toolkit
outperforms Spec Kit, OpenSpec, another model, or another coding host. No upstream
code or instruction text was vendored. The new implementation uses the project's
existing MIT-licensed files and Node standard library.

## Selected work

1. Optional operation packets solve the concrete inability to read a local
   toolkit folder in another assistant. Exact source labels and hashes make
   the packet reviewable; unavailable execution stays unverified.
2. The evaluator runs real programs against independent expected values instead
   of treating a structural-validator pass as a product-quality score.
3. Retained examples preserve briefs, generated PRDs, executable implementations,
   fixed cases and the broken CSV baseline. Reproduction survives temp cleanup.

UI design and security-audit tools remain capability-specific choices for target
products. Context compression, persistent memory, a full agent orchestrator and
automatically installed skill stacks do not solve the selected gaps. Their
benefit here is UNVERIFIED. Current research did not justify making them core.
